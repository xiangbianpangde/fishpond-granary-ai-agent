# 节点清单

> **状态**：Active · **Stage 4 已解冻（2026-08-21）** · 节点已固化编号并补全至 33 个
> **目的**：用最小可维护结构记录"企业情况"的节点；每个节点标注类型、当前证据等级、待补资料和关联验证项。
> **关联**：`02_关系与依赖.md` 描述节点间关系；`03_待验证清单.md` 列出升级到 E1/E2 所需资料；`04_关系图与图片.md` 为图片版全景。
> **v2 变更（2026-08-21）**：① 全部节点固化 ID（原表无编号）；② 新增 12 个缺失节点（政府监管单位、经验载体、AI 底座、适配层、气象站、6 类数据节点、漂移痛点、熏蒸守则、保密合规）；③ 每个节点增加"关联验证项"列，与 `03_待验证清单.md` 的 V 编号对应；④ 价值节点前缀改为 `VAL-`，避免与待验证项 `V-xx` 冲突。

## 1. 节点分类

| 类型 | 含义 | 示例 |
|---|---|---|
| 组织 O | 部门、角色、责任人 | 现场负责人、设备运维、政府对接人 |
| 系统 S | 业务/物联网/数据/安全系统 | 渔业溯源、粮库一卡通、视频安防 |
| 设备 D | 传感器/控制器/网关/PLC | DO 传感器、智能控制柜、门禁 PLC |
| 数据 DT | 关键字段/字段表/接口契约 | DO、pH、水温、仓内温湿度 |
| 痛点 P | 现状 + 触发 + 影响 | 夜间溶氧骤降、熏蒸期误入 |
| 知识 K | SOP / 病例 / 处置预案 | 病害 SOP、应急处置预案 |
| 合规 C | 政府/监管/保密 | 县级储备粮监管字段 |
| 价值 VAL | Demo 想证明的事 | 闭环能力、安全独立、决策可解释 |

## 3. 节点编号规则

- 组织节点：`O-{编号}`；系统节点：`S-{编号}`；设备节点：`D-{编号}`；数据节点：`DT-{编号}`
- 痛点节点：`P-{编号}`；知识节点：`K-{编号}`；合规节点：`C-{编号}`
- 价值节点：`VAL-{编号}`（**v2 起**改用三字母前缀，避免与待验证清单的 `V-xx` 验证项编号冲突）
- 带 ⭐ 的原有节点表示在本轮补全中获得关键验证项标注；带 ⭐新 的为本轮新增。

## 4. 升级规则

- 节点证据升级到 E1/E2 后，把状态从"未验证"改为"已验证"，并在备注中记录来源；
- 节点缺失时，新增节点并补一行 §2 表格；
- 任何节点从行业资料补全时，标 `[行业共性]`，不与项目方特异性混淆；
- **仍需验证的内容**统一看 `03_待验证清单.md`：V-01～V-10 为高优先级闸门，V-11～V-25 为中低优先级；在取得 E1/E2 证据前，所有节点保持当前证据等级，不得升级。

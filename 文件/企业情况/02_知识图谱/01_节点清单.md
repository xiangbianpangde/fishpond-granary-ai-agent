# 节点清单

> **状态**：Active · 渐进更新中  
> **目的**：用最小可维护结构记录“企业情况”的节点；每个节点标注类型、当前证据等级、待补资料。  
> **关联**：`02_关系与依赖.md` 描述节点间关系；`03_待验证清单.md` 列出升级到 E1/E2 所需资料。

## 1. 节点分类

| 类型 | 含义 | 示例 |
|---|---|---|
| 组织 | 部门、角色、责任人 | 现场负责人、设备运维、政府对接人 |
| 系统 | 业务/物联网/数据/安全系统 | 渔业溯源、粮库一卡通、视频安防 |
| 设备 | 传感器/控制器/网关/PLC | DO 传感器、智能控制柜、门禁 PLC |
| 数据 | 关键字段/字段表/接口契约 | DO、pH、水温、仓内温湿度 |
| 痛点 | 现状 + 触发 + 影响 | 夜间溶氧骤降、熏蒸期误入 |
| 知识 | SOP / 病例 / 处置预案 | 病害 SOP、应急处置预案 |
| 合规 | 政府/监管/保密 | 县级储备粮监管字段 |
| 价值 | Demo 想证明的事 | 闭环能力、安全独立、决策可解释 |

## 3. 节点编号规则

- 组织节点：`O-{编号}`
- 系统节点：`S-{编号}`
- 设备节点：`D-{编号}`
- 数据节点：`DT-{编号}`
- 痛点节点：`P-{编号}`
- 知识节点：`K-{编号}`
- 合规节点：`C-{编号}`
- 价值节点：`V-{编号}`

> 第一轮暂不强制编号；后续把节点固化时再补 ID。

## 4. 升级规则

- 节点证据升级到 E1/E2 后，把状态从“未验证”改为“已验证”，并在备注中记录来源；
- 节点缺失时，新增节点并补一行 §2 表格；
- 任何节点从行业资料补全时，标 `[行业共性]`，不与项目方特异性混淆。

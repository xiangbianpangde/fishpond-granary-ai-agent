## 4. AI 竞争格局（v0.3 新增 · Sol P0-1）

> **目的**：明确"为什么这个项目需要 AI Agent 而不是别的方案"，回答"AI 替代方案"的问题。

| 方案 | 优势 | 不足 | 适用场景 | 在本项目中的位置 |
|---|---|---|---|---|
| **传统自动化平台**（PLC + 阈值告警） | 稳定、易维护、监管接受度高 | 无智能、无预测、参数固化 | 已有 IoT 的常规监控 | 客户已有；AI 不替代 |
| **规则系统**（专家系统 + 决策树） | 可控、可解释 | 泛化弱、需大量人工维护 | 业务规则清晰、变化少 | 可作为 Safety Rule 内核 |
| **传统机器学习模型**（时序 / CV / 异常检测） | 专业能力强、可解释 | 需特征工程、跨任务迁移差 | 单点异常 / 识别 | 作为 Agent 的"专业模型" |
| **大模型 Agent** | 理解 / 推理 / 编排 / 多模态 | 需治理、可能幻觉 | 综合判断 / 任务编排 / 跨域 | **本项目的核心方案** |
| **人机协同**（Agent + 人工） | 风险可控、易落地 | 依赖一线 | 监管敏感、高风险场景 | **本项目的安全边界** |

### 4.1 AI 项目的相对位置

- **不是替代**：传统自动化平台仍有价值，AI Agent 在它之上；
- **不是孤立**：Agent 必须依赖专业模型 + 知识库 + Safety Rule；
- **不是全自动**：监管 / 安全场景必须人机协同；
- **不是万能**：落地依赖 IoT 数据质量和原系统授权。

# 04 · 人员与角色画像

> **回答的核心问题**：Agent 的用户是谁？决策权如何？  
> **本轮变更（v0.3）**：新增 §3 **Agent 用户旅程**，明确"谁会每天打开 Agent"——AI 项目失败经常不是技术，而是没有用户。

## 1. 智慧渔业 Agent 用户画像

```text
值班员 / 操作员
    ↓
查看水质 / 视频 / 告警
    ↓
人工判断
    ↓

    ↓

```

```text

    ↓
值班员确认（L2 默认；白名单场景 L3）
    ↓
执行 + 回读
    ↓
效果评估 + 案例沉淀
```

## 3. Agent 用户旅程（v0.3 新增 · Sol P0-1）

> **目的**：避免"AI 项目没有人用"——明确"谁会在什么事件下、什么频率、当前用什么替代、Agent 提供什么增量价值"。

### 3.1 渔业旅程示例：夜间低氧报警

| 字段 | 内容 |
|---|---|
| 触发事件 | 夜间 DO 下降到阈值以下 |
| 使用频率 | 平均每周 0–3 次（按季节） |
| 当前替代方式 | 值班员收到告警短信 → 起床查看现场 → 经验判断是否开增氧机 |
| 痛点 | 夜间响应慢；起床到操作需要 10–30 分钟 |
| Agent 价值 | 自动检测 + 生成建议 + L2/L3 受控增氧 → 响应时间压到分钟级 |
| 关键交互 | 值班员手机收到告警 → 一键查看原因 → 一键确认增氧 |

### 3.2 粮库旅程示例：熏蒸期人员误入

| 字段 | 内容 |
|---|---|
| 触发事件 | 熏蒸期检测到人员进入熏蒸区域 |
| 使用频率 | 极低（每季度 0–1 次） |
| 当前替代方式 | 保安巡逻 + 视频回看（事后发现） |
| 痛点 | 误入中毒风险；事后才发现已晚 |
| Agent 价值 | L1 实时研判 + 通道 B+ 通知责任人 → 风险即时通知 |
| 关键交互 | 责任人手机收到告警 → 查看现场视频 → 通知保安 / 启动应急 |
| 关键约束 | **Agent 不直接控制门禁**；门禁联动由原硬联锁（通道 B）独立触发 |

### 3.3 粮库旅程示例：粮情异常研判

| 字段 | 内容 |
|---|---|
| 触发事件 | 分层温湿度异常（局部发热 / 结露） |
| 使用频率 | 平均每周 1–5 次 |
| 当前替代方式 | 保管员人工巡检 + 经验判断（高温高湿期受限） |
| 痛点 | 巡检频次低；异常发现晚 |
| Agent 价值 | 时序预测 + 机理校核 + L1 研判 → 提前预警 + 异常粮层定位 |
| 关键交互 | 保管员收到预警 → 查看异常粮层与原因 → 决定是否通风 / 气调 |

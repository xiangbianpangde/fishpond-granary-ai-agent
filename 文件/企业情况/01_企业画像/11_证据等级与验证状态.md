# 11 · 证据等级与验证状态

> **目的**：把证据体系从"规则文件"升级为"字段状态表"——**每一字段都要登记当前等级、目标等级、责任人**。  
> **本轮变更（v0.3）**：新增 §5 **字段证据矩阵**（Sol P0-2），覆盖核心字段而非停留在规则说明。

## 1. 证据等级定义

| 等级 | 含义 | 示例 | 是否可作为决策依据 |
|---|---|---|---|
| **E0** | 未知 | 待补字段 | ✗ |
| **E1** | 项目方口述 / 内部推断 | 背景稿、用户提示词、口头访谈 | ✗（仅作假设登记） |
| **E2** | 企业正式材料 | 接口文档、SOP、监管字段文件、企业资质 | ✓（仅作内部决策） |
| **E3** | 现场确认 | 设备照片、访谈纪要、拓扑图、签字文件 | ✓（可进入现场试点） |
| **E4** | 系统截图 / API 验证 | 系统界面、调用返回、样例数据 | ✓（可进入真实接入决策） |
| **E5** | 实际运行数据 | 连续生产数据、闭环日志 | ✓（可作为 Pilot 验收依据） |

> **原则**：任何字段在表格的"证据"列必须标注等级；未达到 E3 的字段不能进入真实接入决策。

## 2. 等级升级路径

```
E0 未知
 ↓ 收集材料
E1 项目方口述 / 推断
 ↓ 取得正式材料
E2 企业材料
 ↓ 现场确认
E3 现场确认（照片 / 纪要 / 拓扑）
 ↓ 系统验证
E4 系统截图 / API 验证
 ↓ 实际运行
E5 实际运行数据
```

| 升级触发 | 当前 → 目标 | 验证动作 | 责任人 |
|---|---|---|---|
| 取得接口文档 | E1 → E2 | 文档审阅 | 数据工程师 |
| 取得设备清单 | E1 → E3 | 现场盘点 | IoT 工程师 |
| 取得 PLC 寄存器 | E1 → E4 | 设备铭牌 + 调用测试 | IoT 工程师 |
| 取得监管字段规范 | E1 → E2 | 文件签收 | 安全合规负责人 |
| 取得应急 SOP | E1 → E2 | 文本 + 提供人授权 | 业务分析师 |
| 取得现场访谈纪要 | E1 → E3 | 签字或录音 | 业务分析师 |
| 取得系统截图 | E1 → E4 | 截图 + 解释 | 平台工程师 |
| 取得连续运行数据 | E3 → E5 | 时间戳样本 + 统计 | 数据工程师 |

## 3. 验证状态

| 状态 | 含义 |
|---|---|
| 待验证 | 字段尚未填写或仅有材料声称 |
| 部分验证 | 部分子字段达到 E3 以上 |
| 已验证 | 全部子字段达到 E3 以上 |
| 已废弃 | 字段不再适用 |

## 4. 字段证据使用规则

1. **写作**：每个画像字段在表格中带"证据"列，标 E0–E5；
2. **升级**：从 `02_知识图谱/` 取得 E1 节点升级时，回到本表更新等级；
3. **展示**：在汇报或对外材料中，只引用 E3 以上结论；E1/E2 必须显式标注；
4. **冻结**：任何 E4 以上字段在冻结前必须再次核对；
5. **追溯**：所有升级必须写入 `12_画像演进记录.md`。

## 6. 升级流程

1. **取得证据** → 在对应画像文件中标注新等级；
2. **同步证据矩阵** → 在本表 §5 中更新当前等级；
3. **记录升级** → 在 `12_画像演进记录.md` 中追加一行；
4. **影响下游** → 同步 `06_需求分类与发展规划.md`（工作版）中的依赖关系。

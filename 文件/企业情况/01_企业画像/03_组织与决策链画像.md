# 03 · 组织与决策链画像

> **回答的核心问题**：谁拍板？谁负责？谁执行？  
> **本轮变更（v0.3）**：新增 §3 **五主体组织关系矩阵**（监管者 / 产权方 / 运营方 / 建设方 / 使用方），替代原单链假设；明确 AI 项目失败常常因为"找不到真正决策人"。

## 1. 决策链（猜测版）

```text
政府主管部门（粮库监管）
    ↓
企业负责人
    ↓
项目负责人 / 技术负责人
    ↓
业务部门（渔业 / 粮库）
    ↓
现场人员
    ↓
设备供应商 / 系统集成商
```

## 2. 角色 × 权限 × 关注点

| 角色 | 权限 | 关注点 | 证据 |
|---|---|---|---|
| 政府监管（县级储备粮主管部门） | 审批 / 监督 / 报送 | 安全、合规、可追溯 | E4 |
| 企业负责人 | 投资决策 / 战略 | ROI、品牌、长期价值 | E1 |
| 项目负责人 | 项目推进 / 资源协调 | 进度、质量、风险 | E1 |
| 技术负责人 | 技术决策 / 安全审查 | 可靠性、安全、可扩展 | E1 |
| 业务部门主管（渔业 / 粮库） | 业务决策 / 验收 | 效率、合规、安全 | E1 |
| 设备运维 | 维护 / 故障处理 | 稳定、易维护 | E1 |
| 现场人员（值班员 / 操作员 / 保管员 / 保安） | 执行 / 巡检 | 易用、可靠 | E1 |
| 资深经验人员（资深养殖户 / 保管员） | 经验输出 | 经验可沉淀 | E1 |
| 设备供应商 | 设备维护 / 升级 | 兼容性、升级路径 | E1 |
| 系统集成商 | 数据平台 / 接口 | 接口成熟度、SLA | E1 |

## 3. 五主体组织关系矩阵（v0.3 新增 · Sol P0-2）

> **目的**：把"政府主管部门"和"企业"按 **监管者 / 产权方 / 运营方 / 建设方 / 使用方** 五个角色拆开，现实中这五者通常不是同一主体。

| 主体角色 | 典型主体 | 决策权 | 主要责任 | 当前猜测 | 证据 |
|---|---|---|---|---|---|
| **监管者** | 县级粮食主管部门 / 农业农村部门 | 政策制定 / 监督检查 / 报送审批 | 政策合规、报送审核 | `[猜测]` 县级粮食和物资储备局 | E4 |
| **产权方** | 政府 / 上级公司 / 股东 | 资产所有权 / 重大投资决策 | 资产保值、长期规划 | `[猜测]` 上级主管单位 | E1 |
| **运营方** | 项目方 / 企业 | 日常运营 / 业务决策 | 生产、保管、合规执行 | `[猜测]` 项目方 | E1 |
| **建设方** | 系统集成商 / 设备供应商 / AI 项目方 | 技术方案 / 实施 / 升级 | 系统建设、接口、升级 | `[猜测]` 多方 | E1 |
| **使用方** | 一线值班员 / 保管员 / 操作员 | 执行 / 巡检 / 反馈 | 落地使用、数据录入 | `[猜测]` 一线员工 | E1 |

> **关键洞察**：政府和粮库项目的风险不只在技术可行性，更在 **AI 项目方是否被授权接入**。监管者、产权方和运营方可能不是同一主体，**Demo/Pilot 验收签字链必须五者都确认**。

## 4. AI 项目决策链调研要点（Q7）

- 谁是 Demo/Pilot 的最终签字人？
- 谁批准接口开放与数据接入？
- 谁承担 AI 建议错误的责任？
- 谁对粮库原硬联锁负责？
- 谁对监管报送内容负责？
- 监管者 / 产权方 / 运营方 是否是同一主体？

## 5. 升级为已确认的条件

- 取得五主体实际名单与签字人 → 替换 §3；
- 取得甲方组织结构图与决策人 → 替换 §1 与 §2；
- 取得 Q7 责任链清单（责任人、授权人、验收人、只读账号申请路径）→ 替换 §4 全部。

# 02 · 业务与资产画像

> **回答的核心问题**：业务域和资产是什么样的？AI 边界在哪？  
> **本轮变更（v0.3）**：所有资产字段增加 **四阶段状态**——**物理存在 / 数据可见 / 接口可用 / 控制授权**——避免"设备存在 ≠ 数据可用 ≠ AI 可控制"混淆；粮库设备额外标注"原系统厂商授权"。

## 1. 业务域拆分

```
企业
 ├── 智慧渔业（生命资产）
 │     业务目标：赚钱、降本增效
 │     核心流程：投喂 → 调控 → 病害防控 → 数据归集
 │     关键节点：夜间溶氧、动态投喂、病害预警、报表归集
 │     异常事件：泛塘、蟹病、参数固化
 │     当前人工动作：经验判断 + 阈值告警
 │     未来 Agent 入口：预警 / 建议 / 受控增氧 / 报表自动归集
 │
 └── 县级储备粮库（国家保障资产）
       业务目标：监管、保障、应急
       核心流程：粮情监测 → 通风/气调 → 出入库 → 监管报送
       关键节点：粮情研判、熏蒸安全、出入库调度、监管报送
       异常事件：发热、结露、虫害、误入、账实不符
       当前人工动作：踏仓巡检 + 经验调控 + 人工登记
       未来 Agent 入口：L1 研判 / 通知留痕 / 自动报表
```

## 2. 资产四阶段状态字段（v0.3 新增 · Sol P0-1）

> **使用规则**：任何资产在表格中必须标注四阶段状态；只有"控制授权"达到 E4–E5 时，AI 才允许做受控执行。

| 字段 | 含义 | 适用证据等级 |
|---|---|---|
| 物理存在 | 设备在场，铭牌/照片可见 | E1–E3 |
| 数据可见 | 能从设备读到数据 | E3–E4 |
| 接口可用 | 接口契约明确 + 调用返回正常 | E4 |
| 控制授权 | 取得写权限或由原系统厂商授权 | E4–E5 |

> **最大风险**："设备存在 ≠ 数据可用 ≠ AI 可控制"——任何阶段未确认前都不能假定下一阶段已具备。

## 5. AI Agent 能力边界

| 资产类型 | AI 能观察 | AI 能理解 | AI 能建议 | AI 能执行 | 备注 |
|---|---|---|---|---|---|
| 水质传感器 | ✓ | ✓ | ✓ | 受控（L2/L3 白名单） | 与设备协议和权限相关 |
| 视频/摄像头 | ✓ | ✓ | ✓ | ✗（不直接控制视频） | B+ 风险识别 |
| 增氧机 | ✓ | ✓ | ✓ | L2/L3 | Q4 协议 + 权限 |
| 索道/料仓 | ✓ | ✓ | ✓ | ✗（不建议自动下发） | 任务规划 + 人工 |
| 粮情传感器 | ✓ | ✓ | ✓ | ✗（不直接控制） | L1 研判 |
| 通风/气调 | ✓ | ✓ | ✓ | L2 | 设备协议 + 旁路 |
| 地磅/RFID | ✓ | ✓ | ✓ | ✗（不直接控制） | 任务关联 |
| 视频安防 | ✓ | ✓ | ✓ | ✗（仅识别） | B+ 风险识别 |
| 门禁/熏蒸/气体 | ✓（只读） | ✓（状态判断） | ✓（通知） | ✗（原硬联锁） | Q1 闸门 |

## 6. 升级为已确认的条件

- 资产盘点完成 → 替换 §3 / §4 中"待补"；
- 设备清单 + 协议 → 替换 §4 "接口可用"列；
- 原系统厂商授权 → 替换 §4 "原系统厂商授权"列；
- AI 接入权限矩阵 → 替换 §5 全部列。

# 行业调研草案

> **状态**：Active · 渐进更新中  
> **目的**：用最小工作量梳理渔业和粮库两个行业的 AI 智能体落地经验，识别 Demo 阶段应该聚焦的“可见、可比、可验证”的差异点。  
> **规则**：本文件只放“行业共性 + 落地经验教训”，不直接抄写背景稿或 PRD；项目方特异性需结合实际证据。

## 1. 行业共性观察

| 维度 | 渔业 | 粮库 |
|---|---|---|
| 核心不确定性 | 生物对象（生长、应激、病害） | 物理对象（粮情、结露、虫害、气调） |
| 主要数据形态 | 时序 + 视频 + 气象 | 时序 + 设备状态 + 安防视频 |
| 主要决策窗口 | 分钟级（低氧/设备联动） | 小时–天级（通风/气调），但安防/熏蒸是秒级 |
| 关键合规 | 用药规范、防疫 | 政府监管、安全联动 |
| 主要失败模式 | 数据漂移、模型偏差、机械故障 | 漂移、传感器老化、监管报送缺漏 |
| 知识沉淀方式 | 资深养殖户经验 | 保管员 SOP + 行业标准 |

## 2. 行业落地经验教训（一般性）

1. **AI 不能替代 SOP**：AI 通常是“提醒 + 研判 + 编排”，SOP 是不可替代的兜底。
2. **数据可信度优先于模型精度**：传感器漂移和缺失会直接破坏 AI 决策。
3. **场景闭环要先小后大**：单场景跑通再扩展，跨场景同步推进的风险极高。
4. **安全链路必须独立**：原硬联锁不能被 AI 取代。
5. **政府/合规是项目闸门**：监管接口、授权和保密往往比技术更难。
6. **人机协同优先于自动化**：对一线工作人员的替代越少，落地阻力越小。

## 3. 对 Demo 设计的启发

| 启发 | 落地动作 |
|---|---|
| 先做共性底座 | Agent、Safety Rule、审计、可解释、按场景 SLA |
| 再做单场景闭环 | 渔业 A：夜间溶氧 → 增氧；粮库 B：熏蒸 → 风险研判 |
| 用 Simulator/回放降低风险 | 把不可控现场依赖暂存到 Simulator |
| 强调通道 B 独立 | 任何 AI 路径都不能替代原硬联锁 |
| 把知识库/RAG 留作渐进 | 先做框架和最小检索集，再做行业沉淀 |

# 深度调研第一轮 · 接口与数据证据登记表

> **用途**：把“系统有接口/设备可远程控制”的口头或材料表述，转化为可检查的接口证据。  
> **状态**：待甲方/现场补录。当前空白不代表接口不存在，只代表尚未取得证据。  
> **证据库**：本表与 `01_深度调研第一轮-调研结论.md` 配套使用。

## 1. 填写规则

每个接口至少补齐：

- 系统/设备名称和唯一 ID；
- 接口类型（API、数据库、消息、文件、SDK、PLC、Modbus、OPC、RTSP 等，以现场实际为准）；
- 字段/点位、单位、时间戳和主键；
- 调用或推送频率、响应时延、历史留存；
- 只读/写入权限、授权人和网络边界；
- 成功返回、超时、断线、无权限和异常数据的表现；
- 证据编号及其存放位置。

## 2. 状态值

| 状态 | 含义 |
|---|---|
| 未确认 | 只有材料声称或尚未接触系统 |
| 待文档 | 已要求接口文档/字段表，尚未收到 |
| 待实测 | 已有文档，但尚未调用或现场验证 |
| 只读已验证 | 已能以授权账号读取并回查数据 |
| 模拟写入已验证 | 仅在沙箱/模拟器完成写入和回读 |
| 真实写入已授权 | 取得明确授权并完成受控测试 |
| 阻塞 | 因授权、网络、安全或资料缺失无法继续 |

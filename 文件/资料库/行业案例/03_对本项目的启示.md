# 对本项目的启示

> 只回答：行业已经证明什么、本项目 Demo 应抄什么、绝不能抄什么。

## 1. 能力对照

| 本项目目标 | 行业已常见 | 行业仍少见 | Demo 建议 |
|---|---|---|---|
| A 夜间低氧预警与增氧 | 阈值/红线自动增氧、短信/电话报警 | 多源综合、可解释、Safety Rule、失败降级 | **做差异**：在已有联动之上加 Agent 研判 + L2 确认 + 审计 |
| 索道动态投喂 | 料塔/无人机/投饵船/轨道机；索道多为专利 | 生长+残饵+天气的闭环 Agent | **P1**：先证明水质增氧，投喂用离线/模拟 |
| 蟹病 RAG | 电子日志、专家系统宣传多 | 可验证病例库少 | **P1**，等 SOP |
| B 熏蒸误入 | 氧气不达标不开门、双人扫脸、PH3 锁门（示范/厂商） | 用 LLM 做硬联锁（不应出现） | **只读验证通道 B**；Agent 只做 B+ 通知 |
| 粮情研判 | 电缆测温、平台预警、部分 AI 虫害 | 机理+可信度降级一体 | **可做 L1**，数据质量先打分 |
| 通风/气调寻优 | 规则通风、充氮工艺自动 | Agent 改浓度需授权 | **P1 / Simulator** |
| 监管报送 | 省市平台、一卡通、国储对接 | NL 自动填报生产 | **P1 字段映射** |

## 2. 必须抄的行业做法

1. **渔业**：溶氧连续监测 + 低于安全值动作 + 通知人（FISH-C04 证明能避免全塘覆灭，但不能承诺零损失）。
2. **粮库**：进仓与气体/氧气硬联锁（GRAN-C05）；失联时边缘/PLC 仍锁门（专利与本项目 fail-closed 同向）。
3. **两边**：人防+技防，公开先进库都强调不是无人（成都香城、杭州有限空间）。
4. **设备四阶段**：行业案例里“已上物联网”经常只到数据可见；控制授权另说。继续用 v0.4 四字段，不要把光明/中储粮的“自动”写成甲方已具备。

## 3. 绝不能照搬

| 错误照搬 | 原因 |
|---|---|
| 把中储粮近千库、百万传感器当县级库目标 | 规模与治理层级不同 |
| 用 LLM 替代门禁/熏蒸 PLC | 行业示范全是独立联锁；违反 PRD 通道 B |
| 承诺 24h 溶氧预测、气调浓度自动最优 | 公开材料多为监测+规则；属 P2 |
| 把厂商宣传的 1 秒联动、100% 灭虫当验收 | 证据等级不够 |
| 认为有索道专利=甲方接口可用 | 专利≠现场协议 |

## 4. 对 Stage 2 现场问题清单的增量

在 Q1–Q7 之外，访谈时应追问：

**渔业**

- 现有增氧是阈值自动，还是纯人工远程点按钮？
- 有没有发生过类似桃江的凌晨溶氧骤降？如何处置、有无日志？
- 索道是主干+跨塘分支，还是塘边轨道？急停谁管？

**粮库**

- 进仓是否已有“氧气/磷化氢不达标则门不开”？（对照杭州）
- 门禁是独立安全系统，还是数字粮仓控制柜一体 PLC？（对照 T/CIIA 053）
- 是否已接市/省粮油监管平台？字段能否给 Demo 只读？
- 是否在推氮气气调免熏蒸？若是，场景 B 要同时覆盖缺氧误入。

## 5. 对 Demo 主题的建议（不冻结）

- 行业对照 **强化 A+B 双场景**：A 有明确减灾故事，B 有明确硬联锁标杆。
- Agent 差异化一句话：  
  **行业已会“阈值联动”；本 Demo 验证“研判—解释—权限三维—审计—失败降级”，并且不碰原硬联锁。**

# Stage 2 追加启示（2026-08-21）

> 深读后，第一轮“抄阈值联动、不抄 LLM 硬联锁”结论成立，并收紧三条。

## 7. 收紧后的 Demo 差异化一句话

行业河蟹塘已经会：**10 分钟测水、红线增氧、手机看数、半夜少跑塘**。  
行业示范粮库已经会：**测氧不开门、双人扫脸、有限空间审批、省平台看仓**。  
行业“智能体/大模型”公开能力停在：**问答、方案生成、预测宣传**。

本 Demo 要证明的不是再买传感器，而是：

**多源研判 → 结构化解释 → 权限三维（L0–L3 分模块）→ Safety Rule 校验 → 审计留痕 → 数据不可信时 fail-closed；并且通道 B 独立，AI 不得开门、不得放宽限制。**

## 8. 对黄金场景的增量

| 场景 | 行业新证据 | 对 Demo 的影响 |
|---|---|---|
| A 夜间低氧 | 高淳明确“夏天半夜去塘边开闸”；河蟹蜕壳高峰与溶氧低谷重叠 | 价值叙事从“防泛塘”扩展为“蜕壳窗口保成活”；SLA 仍待现场，不写 60 秒 |
| A 预测 | 中农 24h、蟹联网 0–72h 已在卖数据产品 | **更要禁止**把预测写进硬验收，否则与市面产品比数字、比不过宣传 |
| 投喂 | 河蟹主流是轨道/船/无人机；索道仍近乎专利 | 维持 P1 + Simulator；现场必须问索道急停归属 |
| B 熏蒸误入 | 仁和粮库 2026 年仍强调氧气不开门+双人扫脸 | 通道 B 只读验证路径被行业坐实 |
| B 威胁模型 | 气调杀虫氧可 <2%；全国气调仓容在涨但占比仍低 | 现场若免熏蒸，Scene B 改称“有限空间误入”，覆盖氮气缺氧 |
| 粮情 | 永修 7×5 测温网格 + 省平台；粮科院 21 天预警为规划 | 粮情 L1 可做；21 天预警 = P2 |
| 地方库 | 永修是省储，比中储粮全网更近县级 | 监管报送对标省平台字段，不对标近千库 |

## 9. 对 19 条 P0-SCENE 的行业就绪度（E4）

见 `文件/demo/08_Stage2行业案例与Demo对照.md` §3。结论摘要：

- **行业已常见、Demo 应做差异层**：夜间溶氧研判、阈值增氧之上的 L2/L3 白名单、熏蒸/有限空间 L1 建议、粮情 L1、数据可信度降级、审计。
- **行业有标杆、现场未证则 Simulator**：门禁硬联锁、视频人员检测。
- **行业形态不同、本项目是差异点**：索道投喂。
- **行业宣传超前、Demo 降级**：24h/72h 溶氧预测、21 天虫霉预警、气调浓度自动寻优。

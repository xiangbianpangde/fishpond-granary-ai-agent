## 1. 字段说明

| 字段 | 含义 |
|---|---|
| Req ID | 唯一编号，格式为 `{模块}-{类别}-{序号}`。 |
| 模块 | `渔业` / `粮库` / `共用`。 |
| 场景 | 需求服务的具体业务场景。 |
| 类别 | 见下方 7 类：SCN / AGT / ALG / DAT / INT / SAF / NFR。 |
| 需求名称 | 用简短的动词短语说明要做什么。 |
| Agent 自动化等级 | 只在 SCN / AGT 中填写；ALG / DAT / INT / SAF / NFR 填 N/A。 |
| **当前优先级** | `P0-BASE` / `P0-SCENE` / `P1`（判定规则见 §3）。 |
| **升级规则** | `无` / `场景入选后升 P0` / `项目级硬要求`。 |
| 状态 | 使用文档顶部列出的状态值。 |

> **完整的 19 字段模板见 §5 BASE 需求明细**；轻量索引见 §4。

## 2. 类别编码（7 类）

| 编码 | 类别 | 含义 |
|---|---|---|
| **SCN** | 业务场景需求 | 针对一个业务痛点的完整场景。 |
| **AGT** | Agent 决策 / 编排需求 | 智能体如何判断、安排任务并与人交互。 |
| **ALG** | 模型 / 算法需求 | 时序预测、视觉识别、异常检测和寻优等专业能力。 |
| **DAT** | 数据 / 知识需求 | 数据接入、知识库建设以及 SOP / 标准整理。 |
| **INT** | 系统 / 设备接口需求 | 调用平台或设备所需的接口。 |
| **SAF** | 安全 / 合规需求 | 权限、熔断、审计和合规约束。 |
| **NFR** | 工程非功能需求 | 性能、可解释、可追溯和可维护性。 |

## 3. 优先级判定准则

| 等级 | 判定条件 |
|---|---|
| **P0-BASE** | 项目级硬要求，**不依赖场景选型**；缺少其中任何一项，Demo 就无法通过项目级硬验收（见 PRD §10.3）。目前共 9 条。 |
| **P0-SCENE** | 候选场景一旦入选 Demo，就升级为该场景的硬验收要求；在场景确定前保持“已规划、未冻结”。 |
| **P1** | 能明显提升 Demo 的说服力，但不影响项目级验收，例如天气融合、可解释输出、自然语言查询、简单看板、视觉辅助、RAG 和知识库最小检索集。 |

**P2 实验能力池**（本轮不纳入需求表，留待 Pilot 阶段）：
- 提前 24h 准确预测溶氧
- 病害提前 1–3 天准确预警
- AI 自动修复 / 校准老旧传感器
- 持续自主学习 / 阈值自优化
- 因果推理(causal inference)
- 多仓多塘全局最优调度
- 完整行业知识图谱
- 监管正式报表自动生成

## 7. 收尾说明

- 本表共 **57 条**需求：**P0-BASE 9 + P0-SCENE 19 + P1 29 = 57**。
- **P2 实验能力**（自主学习、全局调度、因果推理、自动修复传感器等）不在本表，已在 §3 单独列出。
- v0.3 将 BASE 收敛为 **9 条**，全部属于共用底座，不带具体场景含义。
- 深度调研完成后，需求池将根据知识图谱和接口验证结果迭代为 **v0.4**，重点更新：
  - 数据依赖（`待调研` → `已验证` / `需补充` / `需模拟`）；
  - 接口依赖（同上）；
  - 新增或删除条目（依据企业真实 SOP 和政府监管字段）；
  - 优先级（依据真实接口成熟度）；
  - P0-SCENE 激活情况（依据最终场景选型）；
  - Baseline Workflow 和承接率基线（参见 PRD §10.6）；
  - **冻结 Demo 安全负例测试集**（参见 PRD §10.6.6）。

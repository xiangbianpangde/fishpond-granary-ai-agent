## 1. 四维分类法（v0.2 接口细化）

| 分类 | 标签 | 含义 | 触发条件 |
|---|---|---|---|
| **IoT 补齐** | **I** | 需要新增、改造或验证**物理硬件**和**设备接口**（PLC、传感器、控制器） | 现场硬件就位，设备接口协议确认 |
| **AI 开发** | **A** | 只需软件、模型或 Agent，**不依赖新增物联网设备** | AI 框架就绪，数据可用 |
| **共用基础** | **B** | 横跨两端的**软件接口**（API、数据库、SDK）和**数据集成**（跨平台治理） | 数据和 AI 两侧就绪 |
| **商务与法规** | **C** | 需要甲方或政府配合（数据、接口、SOP、备案或授权） | 甲方或政府完成相应工作 |

**接口分类细化(v0.2 新增)**:
- **设备接口** = PLC / 传感器 / 控制器 → **I**
- **软件接口** = API / 数据库 / SDK / 视频流 SDK → **B**

> **重要修正**：COMMON-INT-001 接入的是软件接口，之前归为 I 过于笼统，现在统一归为 **B**（数据接入适配层）。

**判断规则**：
- 需要**新增、改造或验证物理硬件** → I；
- 需要**新增或改造设备接口**（如 PLC 协议）→ I；
- 需要**接入或对接软件接口**（如 API / DB）→ B；
- 只需要**软件、算法、Agent 或数据处理** → A；
- 被**甲方、政府或法规要求**阻塞 → C；
- 同一需求可以使用多个标签，例如 I+A 表示同时需要硬件和 AI。

**第一轮关键观察**：
1. **AI 工作可以先行，但只能在 Simulator/回放或离线样本上先行**；不能把 AI 可开发误写成真实闭环可用。
2. **I 阶段的第一任务是核验，不是立即采购**：当前没有证据证明哪些硬件缺失、哪些设备确实在线。
3. **B 是共同阻塞层**：接口类型、字段、主数据、历史留存和权限均未提供，真实数据接入工作量不能估算。
4. **C 是项目启动闸门**：Q1 原硬联锁和 Q7 授权链可能让技术可行的场景无法落地。
5. **分类已与需求池解耦**：本工作版可修订；冻结的 `04_Demo需求池.md` 仍保持原始基线。

## 8. 关键风险与备选路径

| 风险 | 触发条件 | 备选路径 |
|---|---|---|
| **Q1 原硬联锁不存在** | 调研结论 | 用独立 PLC + Simulator 做 Demo;Pilot 阶段采购 |

- 只做黄金场景 A(夜间低氧,渔业)

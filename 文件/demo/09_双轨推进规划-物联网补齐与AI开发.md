## 2. 双轨划分

### 2.1 划分标准

| 轨道 | 收录范围 | 判定标准 | 进度控制权 |
|---|---|---|---|
| **T1 物联网补齐轨** | E0 闸门 + I 类 + B 类需求 | 需要**现场事实、物理硬件、设备协议、控制权限或业务系统接口**才能推进 | **不由团队决定**——由甲方授权、现场准入和接口开放节奏决定；第一任务是**核验**，不是采购 |
| **T2 AI 开发轨** | A 类需求的全部 + 混合类需求的 A 分量 | 不依赖现场写权限，可在 **Simulator / 回放 / 离线样本**上开发验证 | **由团队决定**——可立即全速启动；一切产出标记"模拟" |
| **交汇点** | 场景闭环集成验证 | T1 闸门通过后，T2 成果才允许接真实数据 / 受控动作 | 双轨同步机制决定（见 §5） |

### 2.2 需求分布（对应 57 条）

```text
T2 可立即启动 ── A 纯 AI/软件 30 条（52.6%）
                 ＋ A+I / I+B / A+I+B / A+C 中属于软件侧的分量

T1 待核验补齐 ── 含 I 共 16 条：I(5) + A+I(4) + I+B(2) + A+I+B(5)
                 含 B 共 13 条：B(6) + I+B(2) + A+I+B(5)

C 外部叠加   ── A+C 5 条：SOP / 监管字段 / 授权链，随 T1-0 一并催收
```

### 2.3 两轨的本质差异

| 维度 | T1 物联网补齐 | T2 AI 开发 |
|---|---|---|
| 当前最大风险 | 材料声称 ≠ 现场事实（R-调研-10） | 把"模拟跑通"误写成"现场可用" |
| 第一动作 | 发 P0 资料请求包 + Q7 授权链确认 | Agent 底座 + Simulator 数据生成器 |
| 完成标志 | 设备台账 / 协议 / 在线率 / Q1 结论有 E1/E2 证据 | 安全负例集 100% 阻断 + 承接率可在模拟场景计算 |
| 失败降级 | 无证据 → 只做独立 Simulator，不采购 | 模拟结果永远显式标记，不进验收口径 |

## 3. T1 物联网补齐轨 · 执行规划

### T1-0 事实与授权（第 0–2 周，立即启动，无需准入）

| 动作 | 最小交付物 | 对应闸门 |
|---|---|---|
| 发出 P0 资料请求包：设备清单、点位表、接口字典、原硬联锁核验报告、监管字段、SOP/病例/预案清单、授权链 | `../../资料库/深度调研第一轮/02_接口与数据证据登记表.md` 开始出现 E2 记录 | E0 |
| 确认 Q7 责任链：业务负责人 / 系统负责人 / 安全负责人 / 授权人 / 验收签字人 | 责任链纪要（E2） | 解锁现场准入 |
| 申请只读账号与沙箱边界（书面许可） | 权限矩阵草案 | Q4 |

### T1-1 设备与接口核验（第 2–6 周，需现场准入）

| 核验对象 | 必须拿到的证据 | 关联需求 |
|---|---|---|
| 渔业 DO/pH/水温传感器 | 点位表、采样周期、心跳/缺失率、校准记录 | `FISH-DAT-001` |
| 渔业控制柜/增氧机 | PLC 型号、协议、寄存器、回读状态、急停与人工旁路 | `FISH-INT-001` |
| **粮库原硬联锁（最高优先级）** | 拓扑/照片/PLC 信息 + **断开 AI 链路的独立触发测试记录** → Q1 结论 | `GRAN-INT-001`、`GRAN-SCN-001` |
| 粮库视频平台 | 流地址/SDK、覆盖、存储、权限 | `GRAN-INT-002` |
| 粮库分层温湿度 | 仓房/层/点位、在线率、漂移抽测样本 | `GRAN-DAT-001/002` |

**决策点 D-Q1（约第 6 周）**：Q1 有 → 场景 B 走真实通道 B 只读验证；Q1 无 → Demo 用独立 PLC + Simulator，Pilot 阶段再议采购。

### T1-2 数据平台接入（第 4–10 周，可与 T1-1 并行）

- 至少 **一个真实只读接口 + 一个回放接口** 打通（渔业溯源系统优先）；
- `COMMON-INT-001` 从 Mock 模式切换出 Real 适配器；
- 交付物：字段字典、主数据 ID 映射、脱敏历史回放包、失败方式说明。

### T1-3 缺口补齐决策（核验完成后）

只有核验证明缺口存在，才进入硬件采购/改造立项；否则仅做软件适配。**核验前不做任何采购承诺。**

## 5. 双轨同步与交汇

### 5.1 同步机制

- **每周一次**双轨对齐：T1 更新证据登记表 → T2 用真实字段/样本替换 Simulator 参数（字段名、单位、采样周期逐项替换）；
- T1 每取得一份 E1/E2 证据，T2 对应模块从"模拟"升级为"真实数据验证"，升级记录写进证据登记表。

### 5.2 交汇条件（集成验证启动闸门，对应 06 阶段 C/D）

同时满足方可进入真实联调：

1. Q1 已有结论（有/无均可，但必须有证据）；
2. 至少一个真实只读接口 + 一个回放接口稳定运行；
3. 受控写入沙箱有书面许可（或明确走纯 Simulator 路径）；
4. Q7 验收签字人确认。

### 5.3 三种交汇情景

| 情景 | 条件 | 动作 | 对应备选路径 |
|---|---|---|---|
| ① 全绿 | 上述 4 条满足 | 双轨合并，进入阶段 C/D 真实集成 | — |
| ② 部分绿 | 仅渔业侧闸门通过 | 聚焦黄金场景 A 单场景集成，粮库维持 Simulator | 路径 B |
| ③ 红 | Q1/Q7 持续无证据 | 纯 Simulator Demo 交付，转"AI Agent 框架产品"路径 | 路径 A |

## 1. 执行摘要

按河蟹塘和县级储备粮两条模型深读公开案例后：

1. **黄金场景 A（夜间低氧）在行业里已经是“阈值增氧 + 手机告警”**，河蟹产区还叠加蜕壳窗口缺氧。Demo 的差异不在“再测一次溶氧”，而在多源研判、可解释、L2/L3 权限和失败降级。
2. **黄金场景 B 的行业标杆是测氧不开门 + 双人身份 + 有限空间审批**，执行主体是门禁/作业平台，不是大模型。绿色储粮少熏蒸**不能取消 B**，因为气调仓缺氧风险更高。
3. 市场上已出现“大闸蟹智能体”“粮仓大模型/21 天预警”宣传。这些能力停在问答、预测、方案生成。若 Demo 去比 24h/72h 预测精度，会输给宣传口径；应比 **治理闭环**。
4. 空天渔场的 **跨塘索道** 在公开投产案例里几乎找不到同构对象（仅专利 + 塘边轨道/船/无人机）。索道维持 P1 + Simulator。
5. 地方库可对标对象是 **江西永修省储** 这类“电缆网格 + 省平台 + 远程通风”，不是中储粮近千库。

## 4. 必须抄 / 绝不能抄（给 Demo 开发的短清单）

### 4.1 必须抄

1. 溶氧连续监测 + 低于安全值动作 + 通知人（可自动开增氧，但必须能人工接管）。
2. 进仓先测气，氧气/毒气不达标则门不开；双人；有限空间审批。
3. 粮情用电缆网格而不是“仓内一个温度计”；异常先定位到层/点。
4. 人防 + 技防并存，不宣传无人粮库/无人渔场。
5. 监管数据与省/市平台对齐的字段意识（即使 Demo 只做映射沙箱）。
6. 设备“已上物联网”拆成四阶段：可见 / 可远程 / 可自动规则 / 允许第三方写。

### 4.2 绝不能抄

| 错误 | 原因 |
|---|---|
| 用中农/蟹联网的 24h、0–72h 溶氧预测当验收 | PRD 已降 P2；宣传不可复现 |
| 用粮科院 21 天虫霉预警当验收 | 规划口径 |
| 用 LLM 替代门禁/熏蒸 PLC | 违反通道 B；行业示范也不是这样做 |
| 把塘边轨道、无人机、料塔写成甲方索道已可用 | 形态不同 |
| 把中储粮近千库当县级库 KPI | 规模与治理不同 |
| 认为免熏蒸就删场景 B | 气调缺氧仍在 |
| 把厂商 100% 灭虫、1 秒联动当验收 | 证据弱 |

## 5. 对现场 Q1–Q7 的增量问题（回写 05）

**渔业**

1. 现有增氧是塘口阈值自动、中控远程点按钮，还是都不能写？
2. 有没有蜕壳期/凌晨溶氧骤降日志？当时谁开的增氧、多长时间？
3. 水质采样实际周期是 1 分钟、10 分钟还是更长？缺失率多少？
4. 索道是主干+跨塘分支还是塘边轨道？急停按钮在哪、谁有权？
5. 投喂是否已有“降雨/低氧停投”规则？

**粮库**

1. 进仓是否已有“氧气或磷化氢不达标则门不开”？是独立安全系统还是控制柜一体 PLC？
2. 是否强制双人？有没有有限空间作业审批电子流？
3. 平房仓测温电缆水平/垂直间距？是否按 GB/T 26882.1-2024 验收？
4. 是否已接市/省粮油监管平台？字段能否给 Demo 只读？
5. 是否在推氮气气调免熏蒸？若是，Scene B 文案改为有限空间误入。

## 6. 对主题候选的影响（不冻结选型）

| 候选 | 行业对照后 | 备注 |
|---|---|---|
| A 夜间低氧 | **更应优先**：痛点故事与河蟹蜕壳窗口都被公开案例坐实；Simulator 可先跑 | 不要升级预测承诺 |
| B 熏蒸/有限空间 | **仍应并列**：示范库已给出通道 B 做法；本项目价值是 B+ 与 fail-closed | 依赖 Q1 |
| C 粮情研判 | 可作 A/B 之外的第三候选，地方库电缆+平台已常见 | L1 足够 |

| F 库区安防 CV | 香城有，但 PRD 已把视频移出通道 B | P1 |

## 7. 资料与缺口

**已核验仍有效**：FISH-C01 部委页、FISH-C02 浙江在线、FISH-C03 苏州农农局、GRAN-C05 粮食和储备局转载 + 杭州网。

**本轮缺口（公开源不足）**：

- 河蟹塘分钟级水质的独立实测论文少，10 分钟是目前最硬的公开采样周期。
- 索道投产项目除专利外几乎没有接口级报道。
- 老旧仓传感器漂移幅度、校准周期没有可引用的县级库公开数字。
- 县级库熏蒸门禁联锁的直接报道少于省级示范库。

以上缺口只能由 `05` 的现场 Q1–Q7 关闭，不能用行业案例填。

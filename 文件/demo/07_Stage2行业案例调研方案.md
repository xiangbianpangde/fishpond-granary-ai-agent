## 0. 本子轨要解决什么

第一轮已有 `05` 现场核验框架（Q1–Q7）和一版公开案例卡（FISH-C01–C07、GRAN-C01–C09）。缺口是：

1. 案例还不够 **河蟹 / 县级粮库** 定向，部分仍是通用鱼塘或中储粮全网规模；
2. 案例与 **Demo 需求 ID**（FISH-SCN-001、GRAN-SCN-001 等）尚未逐条对照；
3. 还没有写清：**行业已证明什么、Demo 应抄什么、绝不能承诺什么**。

本子轨只补这三件事。现场接口、硬联锁、授权仍走 `05`，不在本方案里假装已经核验。

## 3. 方法与证据规则

### 3.1 信息源优先级

| 优先级 | 类型 | 用法 |
|---|---|---|
| P0 | 部委/省厅典型案例、国家标准/行业标准、粮科院、农科院 | 可写进案例卡正文 |
| P1 | 央媒/省级党报、国资委、粮食和物资储备局转载 | 可写效果数字，但标“材料自称” |
| P2 | 高校论文、发明专利 | 证明确有技术路径，**≠ 现场已投产** |
| P3 | 厂商官网/弱电集成商 | 能力方向可记，证据降级，不得当甲方已建成 |

### 3.2 书写禁令

1. 不得把 E4 写成甲方 Q1–Q7 答案。
2. 宣传数字一律标「材料自称」；单源数字标「未交叉验证」。
3. 「AI」「无人」「智能体」必须拆成：监测 / 阈值联动 / L1 建议 / L2 确认 / L3 白名单写设备。
4. 河蟹案例优先于通用鱼塘；县级/地方库优先于中储粮全网。
5. 与黄金场景无关的安防 CV、出入库调度只作对照，不升为 Demo 硬验收。

### 3.3 案例卡字段（资料库统一）

```text
ID / 主体 / 作业形态（河蟹塘或县级库）
能力栈（监测 / 联动 / 建议 / 控制 / 安全联锁）
与本项目最接近的 1–2 个需求 ID
可抄 / 不可抄
来源 URL + 日期 + 来源类型
证据备注（材料自称 / 单源 / 专利≠投产）
```
